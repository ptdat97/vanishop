> Cập nhật lần cuối: **2026-11-08** (Core 0.3.104). Gần đây: tách vận hành kho sang plugin `vani.warehouse` (ADR-042); giữ Fulfillment trong Core (ADR-043); bổ sung luồng xử lý đơn/đổi trả, danh sách sản phẩm phục vụ vận hành và sửa xử lý mã giảm giá không hợp lệ. Backlog Admin SME hiện hành ở [reference-parity-refactor §6, L26](../20-roadmap/reference-parity-refactor.md). Cập nhật tài liệu này trong PR làm thay đổi trạng thái capability.

## Thang trạng thái

| Trạng thái | Nghĩa |
|---|---|
| **Implemented** | Code đã có, có test pass, dùng được theo đúng tài liệu |
| **Partially Implemented** | Đã có code nhưng thiếu phần đã thiết kế (ghi rõ thiếu gì) |
| **Designed** | Có thiết kế chi tiết trong `docs/`, chưa có code |
| **Planned** | Mới có ý định hoặc phác thảo, chưa có thiết kế chi tiết |

## Tổng quan

> **Slice 12d (microkernel, [ADR-029](../19-adr/ADR-029-commerce-microkernel.md)) đã có code (2026-10-02)**: COD, chuyển khoản, phí giao cố định, VAT VN là **plugin hệ thống** `vani.cod`, `vani.bank-transfer`, `vani.shipping-flat-rate`, `vani.tax-vn-vat` (manifest `"bundled": true`, cấu hình qua Admin → Cấu hình, `.env` là mặc định); `php artisan vani:install` cài + bật; extension point bắt buộc (`Extensions::requires`) — không tắt được implementation cuối, doctor báo thiếu; Core giữ `NoTax` dự phòng; arch test R28. **0.3.39**: vòng 0 không còn tên tài nguyên thương mại (module khai báo `AdminScreen::declareResource`), Core không còn mã `cod`/`vn_vat_inclusive` (đơn đổi hàng chọn cổng theo `collectsOnDelivery`, cảnh báo theo capability), arch test R29 + R28 mở rộng ([commerce-kernel §10](../02-architecture/commerce-kernel.md)). **0.3.41**: múi giờ, ngôn ngữ, tiền tệ, định dạng, rate limit, OTP, breaker… ở `config/vanishop.php` (`StoreClock`, `StoreLocale`); form bản dịch Admin theo ngôn ngữ cấu hình; sửa lệch giờ khung bảng giá. **0.3.42**: luật SĐT VN là plugin hệ thống `vani.phone-vn` (`PhoneNumberPolicy`, Core giữ `international`). Reporting là plugin `vani.reports` (0.3.12).

> **Slice 12 (một cửa hàng, [ADR-028](../19-adr/ADR-028-single-store-brand-as-catalog.md)) đã có code (2026-10-02)**: gỡ module Brand (tenant) và Channel, `BelongsToBrand`/`BrandScope`, brand workspace trong Admin, bảng `plugin_scopes` và bật plugin theo scope brand, header `X-Vani-Channel`, settings nhiều cấp. Brand là thực thể Catalog (`Catalog\Persistence\Models\Brand`, Admin `/catalog/brands`, `styles.brand_id` tuỳ chọn), Storefront API `GET /brands`, `/brands/{slug}`, lọc `?brand=` + facet `brands`, snapshot `brand_id`/`brand_name` trên dòng đơn, rule khuyến mãi `in_brands` (plugin `vani.promotion-rules`), giỏ nhiều brand → một đơn, số đơn một dãy `VN<yymm>-<6 số>`, nguồn đơn `orders.source` (header `X-Vani-Source`), thống kê mua trên `customers`. Core `0.3.0`.

> **Slice 0 (Foundation) đã có code**: khung module, Shared, Tenancy tối thiểu, Identity (RBAC theo phạm vi, audit, đăng nhập Admin), Extension (hook + plugin system + CLI), khung Admin Inertia, plugin mẫu, CI. Chưa có giỏ, checkout, đơn.
>
> **Slice 1–9b đã có code**: Catalog, Product, Variant & Price, Inventory (giữ hàng không oversell, đã kiểm chứng bằng concurrency test nhiều tiến trình trên MySQL), Cart, Checkout (khuyến mãi + voucher, VAT, phí giao cố định, đặt hàng idempotent), Payment (COD, chuyển khoản thủ công, khung cổng online + IPN, hết hạn thanh toán, hoàn tiền), quản lý đơn (Admin, tra cứu/huỷ cho khách), giao hàng (vận đơn thủ công + khung hãng vận chuyển, webhook, trừ tồn khi xuất kho, thu COD, hoàn tất đơn) — luồng E2E COD chạy đầu-cuối qua API; đổi/trả (yêu cầu của khách, duyệt, nhận hàng, nhập kho, hoàn tiền).
>
>
> **Slice 10 (Proof plugins) đã có code**: ba plugin chứng minh kiến trúc thật sự cắm vào extension point của Commerce Core mà không vá Core — `vani.promotion-rules` (rule điều kiện khuyến mãi), `vani.vietqr` (cổng thanh toán QR động), `vani.ghn` (hãng vận chuyển + báo cước checkout). Mỗi plugin có contract test của Core, config riêng và bật/tắt cho cả cửa hàng.
>
> **Slice 11 (Integration platform — phần lõi) đã có code**: module `Integration` với event feed + transactional outbox/inbox, worker nhiều tiến trình (`SKIP LOCKED`, giữ thứ tự theo đơn), retry/backoff/dead letter/replay, webhook ký HMAC cho đối tác, extension point `Connector`/`InboundHandler` cho plugin, Integration Client (key HMAC xoay vòng, scope, IP allowlist, rate limit), Integration API v1 (event feed, đơn hàng, xác nhận đơn, đồng bộ tồn từ authority ngoài), màn hình Admin "Tích hợp". Chưa có connector ERP cụ thể (chờ chốt ERP).
>
> **Slice Customer đã có code**: tài khoản khách hợp nhất theo SĐT, đăng nhập OTP/mật khẩu (token Bearer, ADR-024), profile ẩn cho khách vãng lai (lịch sử đơn tự về tài khoản khi đăng ký), sổ địa chỉ, consent theo kênh × mục đích, merge, ẩn danh hoá, xuất dữ liệu, gộp giỏ khi đăng nhập, Admin khách hàng.
>
> **Slice Notification đã có code**: mẫu tin theo loại × kênh × ngôn ngữ, nhật ký gửi idempotent, gửi bất đồng bộ có retry, tin giao dịch đặt/huỷ đơn và giao hàng (email mặc định), consent cho tin marketing; plugin `vani.sms-brandname` (eSMS) và `vani.zalo-zns` là kênh gửi + kênh OTP (ZNS ưu tiên, tự dự phòng sang SMS).
>
> **Tách vận hành kho (Core 0.3.88, 2026-11-06, ADR-042):** các capability nhiều kho, chuyển kho và đối soát snapshot nguồn ngoài được chuyển sang plugin `vani.warehouse`. Core Inventory giữ engine tồn, location mặc định, reservation/ledger và đối soát nội bộ. Xem [inventory](../08-inventory/inventory.md).
